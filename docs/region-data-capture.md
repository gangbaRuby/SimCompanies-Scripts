# 领域数据响应截取

## 范围与调用链

`src/index.js` 导入 `core/requestHooks.js`，后者启动 `core/regionDataCapture.js`。截取属于整页网络层，覆盖 `fetch` 和 XHR；不经 `pageObserver` 初始化，不随 SPA 路由退出停用，也不创建 DOM、Observer 或计时器。

读取副本后把有效计算字段合并到 `SimcompaniesRetailCalculation_<realm>`。原响应、请求参数、错误和重试仍交给原调用方。只接受同源请求，领域数据支持 0、1、2；响应最终 URL 必须与请求路由一致，避免重定向后仍沿用旧领域。重复安装有标记防护，XHR 元数据使用弱引用，单次请求结束或复用时清理本次监听。

## 数据来源

| API | 写入字段与归属 |
| --- | --- |
| `GET /api/v3/companies/auth-data/` | 按 `authCompany.realmId/companyId` 校验公司；更新公司名、销售修正、经济周期和加速倍率；`levelInfo.capabilities.executives === false` 或领域 2 时高管加成为零；挑战另核对 `authCompany.challengeStart` |
| `GET /api/v3/companies-by-company/<realm>/<name>/` | URL 的领域、请求开始时的自己公司、响应 `companyPublicInfo.id` 一致时更新休闲加成和管理费 |
| `GET /api/v3/companies/me/executives/` 或 `GET /api/v3/companies/<id>/executives/` | 必须属于请求开始时本页已确认的自己公司；数字 ID 接口须匹配公司 ID，响应若带 `currentWorkHistory.employerId` 也须一致；`me` 须至少有一条在职记录且所有在职记录的雇主 ID 均与自己公司一致。复用原有高管筛选、学院和加成公式 |
| `GET /api/v4/<realm>/resources-retail-info/` | 按 URL 领域保存品质、资源编号、平均价和饱和度 |
| `GET /api/v2/weather/<realm>/` | 按 URL 领域保存原有 `sellingSpeedMultiplier: { Until, sellingSpeedMultiplier }` 结构 |

同时旁读游戏已有的 `POST /api/v1/realm/<realm>/sync/` 和 `POST /api/v1/challenges/restart/`，仅用来识别切换或重开、使旧身份请求失效；插件不会主动发送这些请求，也不把它们当作新的完整数据更新入口。

## 原有流程的边界

- 不改变手动更新的 API、顺序、次数，不去掉其重复的身份读取。
- 不改变 `autoUpdaters.js` 的轮询、过期判断，也不改变 `network.js` 的重试和天气失败返回值。
- 局部更新保留原有 `timestamp`。截取天气后，其原有到期字段自然变新；完整刷新仍按原有规则判断。
- 高管可有可无，有限数值 0 是有效计算输入。能力明确未解锁或领域 2 时直接写 `adminBonus: 0`、`saleBonus: 0`；旧缓存仅缺这两项也可补齐。解锁后新的有效高管响应恢复正常公式。缺少能力字段或 HTTP 失败不等于没有高管。
- 对明确不具备高管功能的公司，首次无缓存或缓存不完整时，在内存中收齐本次身份、公司管理费/休闲加成、饱和度和天气后才保存；切换或重新查询身份时清空暂存。普通领域公司 ID 冲突仍交给原主动流程恢复。未收齐不写残缺缓存。
- 首次被动收齐使用 `timestamp: null` 表示尚无完整主动更新时间，原更新器的 `new Date(null)` 判定仍会触发过期更新；不伪造当前完整刷新时间，也不让界面显示 1970 年。已有同公司/同轮挑战的完整时间保留。
- 缺失字段不覆盖旧值。已验证数字公司 ID 的空高管列表可以将加成归零；能力未确认且 `me` 空列表无法证明归属时跳过。无效技能、缺工作记录、错误响应、空饱和度列表等保留旧值。
- 不向 UI 额外广播刷新事件；功能下次按原有路径读取领域缓存时使用新值。

## 异步与维护风险

- 带领域的天气和饱和度按 URL 保存，不按响应到达时的页面保存；同领域换公司后，公共字段更新不会附带清零旧公司的高管加成。
- 身份只来自本页成功截取的 `auth-data` 或无并发歧义的 `sync` 响应，不使用 DOM 公司链接、领域图标或旧缓存推断。尚未确认身份时，公司详情和高管均跳过。
- 公司详情、高管在请求发送时记录已确认公司和身份代次。身份查询、领域切换一开始就使此前请求失效，只有最新身份请求成功且不与切换重叠时才恢复。最新请求失败、非法 JSON、匿名/未知领域或重定向时不恢复旧身份。
- 多次切换重叠、切换期间发起身份查询时，不凭响应到达顺序猜测最终身份；等待所有切换结束后的新身份响应。HTTP 错误、网络失败、XHR 取消/超时也会清理在途标记，但不额外发请求。
- 其他标签页的切换不能仅靠本页事件观察，因此 `me` 高管响应还须通过 `currentWorkHistory.employerId` 自证公司归属；没有这个字段时交给原有完整更新，不降低校验。
- 同类截取使用请求序号阻止较早请求或较慢 JSON 解析覆盖较新的截取结果。
- 发送时记录完整缓存时间戳；响应到达前原完整更新或其他标签页已经保存新完整快照时，跳过该局部写入。此机制不建立跨标签页所有局部响应的全局时间排序，也不把多接口响应当成同一时点快照。
- 这不是完整请求调度器：原主动流程与截取仍可同时运行，主动流程最后保存其完整快照的行为保持原样。
- 不保证每次游戏操作都会产生可截取响应。高管到任、培训/罢工结束等时间变化仍依赖游戏后续请求或原有刷新。
- 前端调整端点、`companyPublicInfo.id`、高管技能字段、天气或饱和度结构时，需要重新核对。若游戏改成从其他传输通道读取，这层也需对应维护。

## 验证要求

修改后执行 `npm run check`，并核对正常/错误响应、查看他人公司、身份未确认、DOM 领域误识别、模拟其他标签页更改登录态、领域连续切换、并发身份请求、请求乱序、重定向、缺少缓存、XHR 复用/取消/超时及 `fetch` 的字符串/URL/Request 输入。高管公式提取应与改动前源码对照，覆盖学院 0/5/15、到任时间、罢工、培训、空列表和高点数衰减；主动流程的成功结果、请求序列和失败路径应保持一致。

## 挑战领域（ID 2）与无高管处理

已从本地前端包 `index-ZU2gek09.js` 的领域配置确认：领域 2 为 `Challenge`，`executives: false`、`recBuildings: false`、`retailModeling: 0`、`challenge: true`。普通领域的高管能力在公司 15 级解锁；截取以响应的能力布尔值为准，不根据等级或缺失字段猜测。

- 挑战领域高管、休闲加成为 0，仍须读取有效管理费；本层不为高管补发任何请求。首次收齐与后续局部更新均支持领域 2。
- 领域 2 的请求除 URL 领域外还绑定已确认公司和 `challengeStart`。首次未确认身份、开始时间缺失/无效时不写入；同一公司不接受早于已知挑战轮次的身份或缓存回退。不同公司分别比较轮次。
- 挑战重开发出时清空身份及未完成的收集，使旧公司/天气/饱和度请求全部失效。重开期间的身份响应不能恢复写入；按游戏实际流程刷新页面并取得新身份后恢复。已有缓存未标轮次或与新挑战不同，必须重新收齐，不能把新字段混入旧轮；保存时不继承旧建筑、仓库或其他附加字段。
- `challengeStart` 复用已有领域缓存，随现有领域数据导出登记导出，无新增持久化键。未完成的数据只在页面内存暂存。
- 主菜单在“R2数据”下方展示“挑战领域”状态，读取领域 2 缓存；打开菜单或原有数据更新成功时刷新。没有缓存显示“无数据”，已有缓存但 `timestamp: null` 显示“已获取”，完整更新后显示时间；解析失败显示“数据损坏”。状态行不新增请求或定时器。
- 本层无法看到其他标签页尚未反映到本页身份/缓存的重开；公司详情响应本身不携带轮次，不能宣称获得跨标签页实时一致性。已看到更晚轮次后会拒绝旧轮写入；原主动流程仍可能最后保存其快照。
- 接入范围仅限领域计算数据截取。建筑/仓库截取、通用领域识别、导出入口、零售模型及各页面功能仍各有领域限制，不能据此宣称全插件完整支持挑战领域。

本地回归覆盖无高管、零值、解锁、首次收齐、领域切换、相同公司重开、不同公司轮次、旧响应/旧身份回退和完整刷新竞争。真实浏览器使用本地模拟 API 验证 fetch/XHR；尚未使用实际挑战账号核对接口出现时机及字段样本。
