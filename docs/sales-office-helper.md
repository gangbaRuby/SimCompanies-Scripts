# 销售办公室优化（测试中）

## 功能与数据口径

开关键 `salesOfficeHelper` 沿用 `SC_PageActions_Settings`，不新增持久化键。

- 操作区插在原生货物需求汇总下方：复制总需求、复制当前缺货、复制所有大楼缺货、交单寻优与全部交单按钮。
- 当前需求来自已完成寻单的原生卡片，包含缺货和亏损订单；按资源合并后扣一次可用库存。输出 `BUYING` 与 `:re-ID: x数量`。
- 建筑列表读取 `requestHooks.js` 拦截游戏请求后保存的 `SimcompaniesRetailCalculation_<realm>.buildings`，与餐馆提醒共用。禁止主动 GET `/api/v2/companies/me/buildings/`（会返回 403）。缓存缺失、损坏、公司不匹配或没有当前大楼时，提示先进入地图并刷新，再返回大楼重试。
- 所有大楼缺货点击时经 `window.__SC_Network.requestJson` 读取登录公司、缓存中各销售办公室（`kind === 'B'`）订单以及公司仓库。排除未完成寻单的订单和锁定库存，所有楼合计后只扣一次共享库存。任一楼失败或数据不完整时不复制部分结果。
- 全部交单按钮展开，每笔独立防重复点击；可连续点击不同订单。处理中及订单移除后保留槽位，避免下一笔突然补位。
- 交付仍为真实用户点击原生按钮；仅 CSS 改变视觉位置，不移动 React 节点、不模拟点击、不读取 React 私有状态、不新增提交请求。
- 反馈显示在操作区状态行，剪贴板 API 失败时使用 textarea 降级。

## 寻优口径

默认当前大楼，可切换全部大楼。读取新数据，按资源、品质、数量和库存成本模拟取货，比较订单子集、顺序和每笔高低品质优先组合，目标为现有库存下所选订单合计净利润最大。允许不交单，也允许亏损中间步骤参与搜索，以免错过后续更高利润组合。

每笔净利润 = 基础售价 + 品质奖励 − 实际消耗库存成本 − 该单寻单费用。品质奖励 = 各资源单价 × 实际交付品质数量加权和 × qualityBonus / 100。cost 是整批库存各成本项总和，单位成本需除以该批数量。此目标与游戏显示的会计净利润一致；不按市场重置成本或已支出费用的机会成本计算。

`src/utils/salesOfficeOptimizer.js` 使用分支搜索、乐观上界及状态记忆，每 128 个状态让出主线程。默认最多 30 万状态或 15 秒，也可手动停止。穷尽搜索才显示“最优方案”；停止或达到限制显示“当前最佳（搜索未完成）”。不自动改变品质开关或交付。

结果列出楼名、订单位置、货物、品质选择及预计利润。当前楼编号匹配稳定按钮槽位，其他楼显示读取时的订单顺序。按推荐切换品质保留结果；提交、订单/库存/成本变化、范围变化或离页时作废旧结果。切换其他楼后重新计算。快速并发交单时服务器处理顺序可能不同，实际品质分配和利润可能偏离模拟。

## 调用链与清理

index.js 导入 → pageObserver 匹配 /b/<id>/ → SC_Modules.salesOfficeHelper.init() → 扫描订单 DOM → 注入汇总下方面板并定位原按钮 → 用户触发读取已拦截的建筑缓存、GET 订单/仓库或分片寻优 → 更新面板。

MutationObserver 监听卡片、利润、禁用状态及错误；ResizeObserver、滚动和窗口尺寸事件更新槽位。重复初始化复用实例，切楼排除旧卡片。destroy() 清理 Observer、逐单超时、动画帧、监听、UI 和定位属性，并使异步令牌失效；未完成 GET 返回后丢弃，不再继续后续请求。计算数据仅保留内存。

读取前后核对公司身份和领域；当前楼 API 需求与 DOM 不一致时要求刷新。严格校验订单 ID、时间、资源、数量、品质和成本，空仓库合法。有弹窗时隐藏操作区并恢复按钮；祖先 transform/filter/contain 或层叠遮挡时使用原位置按钮。

## 验证与限制

在 staging 测试大楼时执行 `npm run build:staging`，安装 `dist/autoMaxPPHPL_STAGING_DEV.user.js`。首次使用先更新插件基本数据和当前领域数据；此站点的浏览器存储独立于正式服。普通开发包仅匹配正式服。

运行 npm run check（含 build）。本地验证使用附件真实订单 DOM、离线网络样本和真实模块源码，在 Chromium 检查 1280/390/320px、深浅模式、独立提交、滚动定位、重复初始化、移除恢复、功能开关与离页慢响应；算法与小规模完整枚举对照。离线样本补充基础样式，不等于完整游戏实机验证。

仍需真实游戏验证服务器并发交付、实际成本数据、完整游戏主题与手机浏览器。建筑列表是最近一次游戏请求的快照；新增或拆除建筑后需先让游戏重新加载建筑列表。全部楼订单并非原子快照，其他页面同时交易可能改变库存；推荐只代表读取时的数据。正式安装包仅经 release 流程生成。
